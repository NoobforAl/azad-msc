02 · Tasks

A thread is a task that points at the same objects

Gold arrows: CLONE_VM | CLONE_FILES | CLONE_THREAD share the pointers.

SAY (EN): Each box in amber is a task_struct, one per thread. Process A has two of them with the same tgid; they point at the same mm_struct, file table and signal state. Process B has its own. SAY (FA): هر جعبهٔ نارنجی یک task_struct است، یکی برای هر نخ. پردازهٔ A دو تا با tgid یکسان دارد که به همان mm_struct، جدول فایل و وضعیت سیگنال اشاره می‌کنند. پردازهٔ B مال خودش را دارد. 02 · states

A task is runnable, sleeping, or a zombie waiting for wait()

SAY (EN): R means runnable, whether or not it is on a CPU. Going to sleep counts a voluntary switch; being preempted counts an involuntary one. After exit the task is a zombie until the parent calls wait. SAY (FA): R یعنی قابل اجرا، چه روی CPU باشد چه نه. خوابیدن یک switch داوطلبانه حساب می‌شود و preempt شدن یک switch غیرداوطلبانه. بعد از exit، task تا زمانی که والد wait کند zombie است. KEY POINT: kill -9 cannot remove a zombie; only its parent can. EXAMPLE: Lab 02.1 prints State: Z (zombie) before waitpid. PITFALL: Thinking zombies hold memory; they hold a PID. TIME: 90

SAY (EN): Classes are const structs laid out by the linker in priority order; the core walks them top-down and runs the first task offered. 02 · EEVDF

EEVDF: the earliest deadline among eligible tasks

1eligible: v ≤ V
2vd = v + slice/w
3nice = share, slice = latency
SAY (EN): V is the weighted average virtual time. Tasks at or behind it are owed CPU and are eligible. Among them the earliest virtual deadline wins. A short slice gives an early deadline, so B runs first, but its long-run share is the same. SAY (FA): V میانگین وزنی زمان مجازی است. taskهایی که عقب‌تر از آن یا روی آن هستند طلب CPU دارند و eligible هستند. بین آن‌ها زودترین virtual deadline برنده است. slice کوتاه deadline زودتری می‌دهد، پس B اول اجرا می‌شود، اما سهم بلندمدتش همان است. KEY POINT: Two knobs: weight and slice. EXAMPLE: base_slice_ns = 2800000 on the 8-vCPU VM. PITFALL: Tuning sched_latency_ns: it no longer exists. TIME: 120

02 · Linux vs OpenBSD

Linux shares per resource; OpenBSD splits process and thread

Linux v6.18.63

  • one task_struct per thread
  • kernel_clone() + CLONE_* flags
  • classes: dl, rt, fair, ext
  • EEVDF, RB-tree, O(log n)

OpenBSD 8cada8c

  • struct process + struct proc
  • fork1() vs thread_fork()
  • one scheduler, no RT class
  • 32 queues, ffs(), O(1)
SAY (EN): Linux's design is maximally flexible: containers and vfork come from the same flags. OpenBSD's is simpler to reason about: a thread can only be created inside an existing process, and the 4.4BSD decay-usage priority is cheap but not exactly proportional. SAY (FA): طراحی لینوکس بیشترین انعطاف را دارد: container و vfork از همان پرچم‌ها می‌آیند. طراحی OpenBSD ساده‌تر قابل استدلال است: نخ فقط داخل یک پردازهٔ موجود ساخته می‌شود و اولویت decay-usage در 4.4BSD ارزان است ولی دقیقاً متناسب نیست. KEY POINT: Full trade-off table in kernel-walkthrough §9.4. EXAMPLE: openbsd/sys/kern/kern_sched.c sched_chooseproc(): queue = ffs(spc_whichqs) - 1 PITFALL: — TIME: 90

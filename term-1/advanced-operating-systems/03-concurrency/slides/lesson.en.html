SAY (EN): Read it bottom up. Hardware gives a handful of atomic read-modify-write instructions. The kernel turns them into spinlocks, and builds sleeping locks on top. User space reaches the kernel only through futex() when it must wait. SAY (FA): از پایین بخوانید. سخت‌افزار چند دستور اتمی read-modify-write می‌دهد. کرنل از آن‌ها spinlock می‌سازد و قفل‌های خوابیدنی را روی آن. فضای کاربر فقط وقتی باید صبر کند از راه futex() به کرنل می‌رسد. KEY POINT: The futex syscall is the only boundary crossing. EXAMPLE: strace -f -e futex ./pc_cond PITFALL: Thinking mutex = syscall. TIME: 60
03 · Memory ordering

x86 lets a later load pass a buffered store

SAY (EN): ① Each store goes into the core's private store buffer. ② The following load reads the other variable from cache, still 0. ③ The stores drain later. Both threads read 0, which no interleaving allows. SAY (FA): ① هر store به store buffer خصوصی هسته می‌رود. ② load بعدی متغیر دیگر را از cache می‌خواند که هنوز ۰ است. ③ storeها بعداً تخلیه می‌شوند. هر دو نخ ۰ می‌خوانند، چیزی که هیچ درهم‌آمیزی‌ای اجازه نمی‌دهد. KEY POINT: x86-TSO allows exactly one reordering: store then load. EXAMPLE: Lab 05 sb.c PITFALL: "x86 is sequentially consistent." TIME: 90

03 · Locks

Spin when the wait is short and you may not sleep

spin_lock()

  • busy-waits on the CPU
  • preemption off while held
  • holder must not sleep
  • usable in IRQ context (_irqsave)
  • no owner field

mutex_lock()

  • spins only while the owner runs
  • preemptible
  • holder may sleep
  • process context only
  • owner = task pointer + 3 flags
SAY (EN): Both fast paths are one cmpxchg with acquire ordering. They differ in what a loser does: queue and spin locally, or spin on the owner and then sleep. SAY (FA): مسیر سریع هر دو یک cmpxchg با ترتیب acquire است. فرقشان در کاری است که بازنده می‌کند: در صف بماند و محلی بچرخد، یا روی مالک بچرخد و بعد بخوابد. KEY POINT: Sleeping with a spinlock held is a bug (might_sleep warns). EXAMPLE: "BUG: scheduling while atomic" PITFALL: Using a spinlock in user space, where the holder can be preempted. TIME: 75

static void queued_spin_lock(struct qspinlock *lock){	int val = 0;	if (likely(atomic_try_cmpxchg_acquire(&lock->val,			&val, _Q_LOCKED_VAL)))		return;	queued_spin_lock_slowpath(lock, val);}/* ... */static void queued_spin_unlock(struct qspinlock *lock){	smp_store_release(&lock->locked, 0);}
1whole word 0 → set locked byte: lock cmpxchg
2contended: pending bit, then a per-CPU MCS queue
3unlock is a plain byte store with release order
SAY (EN): spin_lock disables preemption and lands here. One CAS when uncontended. In the slow path each waiter spins on its own per-CPU node, so the lock's cache line stops bouncing. Unlock needs no lock prefix on x86. SAY (FA): spin_lock preemption را خاموش می‌کند و به اینجا می‌رسد. بدون رقابت فقط یک CAS. در مسیر کند هر منتظر روی node مخصوص CPU خودش می‌چرخد، پس cache line قفل دیگر بین هسته‌ها پاس داده نمی‌شود. آزادکردن روی x86 به پیشوند lock نیاز ندارد. KEY POINT: The 32-bit word = locked byte · pending bit · tail (CPU + index). EXAMPLE: kernel/locking/qspinlock.c L277 xchg_tail() PITFALL: On the slide __always_inline and L116-122 (#endif, comment) are elided, and one line is wrapped to fit; the exact excerpt is in kernel-walkthrough.en.md §1.2. 03 · Futex

A futex enters the kernel only when someone must wait

SAY (EN): ① lock is a CAS in user space. ③ On failure the word becomes 2 and the thread calls FUTEX_WAIT. ② The kernel sleeps only if the word still equals 2. ④ Unlock: if the old value was 1, nobody waits, done. ⑤ Otherwise FUTEX_WAKE one thread. SAY (FA): ① گرفتن قفل یک CAS در فضای کاربر است. ③ اگر شکست بخورد کلمه ۲ می‌شود و نخ FUTEX_WAIT را صدا می‌زند. ② کرنل فقط اگر کلمه هنوز ۲ باشد می‌خوابد. ④ آزادکردن: اگر مقدار قبلی ۱ بود کسی منتظر نیست. ⑤ وگرنه FUTEX_WAKE برای یک نخ. KEY POINT: Uncontended lock/unlock = zero syscalls. EXAMPLE: Lab 04 futex_mutex.c (Drepper's mutex 3) PITFALL: Calling FUTEX_WAKE on every unlock: correct but slow. TIME: 90

03 · RCU

RCU readers take no lock; the writer waits a grace period

SAY (EN): ① rcu_assign_pointer publishes the new version with a release store. ② The grace period ends when every CPU has passed a quiescent state; a preempted reader is tracked on blkd_tasks. ③ Only then is the old version freed. OpenBSD SMR detects the grace period by moving its thread onto each CPU in turn. SAY (FA): ① rcu_assign_pointer نسخهٔ تازه را با release store منتشر می‌کند. ② grace period وقتی تمام می‌شود که هر CPU از یک quiescent state گذشته باشد؛ خوانندهٔ preempt‌شده در blkd_tasks دنبال می‌شود. ③ فقط آن‌وقت نسخهٔ قدیم آزاد می‌شود. SMR در OpenBSD با بردن نخش روی تک‌تک CPUها grace period را تشخیص می‌دهد. KEY POINT: "Where is rcu_write_lock()? It does not exist" (rcupdate.h L872). EXAMPLE: synchronize_rcu() tree.c L3341; smr_grace_wait() kern_smr.c L146 PITFALL: Calling synchronize_rcu() inside a reader: self-deadlock, lockdep warns. TIME: 120
03 · Deadlock

AB-BA: a cycle in the wait-for graph stops both threads

1mutual exclusion + hold-and-wait
2no preemption of locks
3circular wait: break it with a global order
SAY (EN): All four Coffman conditions hold here. Lock ordering by address breaks circular wait. Lockdep, TSan and helgrind all report the inverted order even on runs that don't hang. SAY (FA): هر چهار شرط Coffman اینجا برقرار است. ترتیب قفل بر اساس آدرس انتظار چرخه‌ای را می‌شکند. lockdep، TSan و helgrind ترتیب وارونه را حتی در اجراهایی که قفل نمی‌شوند گزارش می‌کنند. KEY POINT: Detect the order, not the hang. EXAMPLE: Lab 06: gdb thread apply all bt shows both threads in futex_wait. PITFALL: Adding a timeout "fixes" the symptom and hides the bug. TIME: 90

Which reordering does x86-TSO allow?

A store → store
B load → load
C store → later load (other address)
D none: x86 is SC
SAY (EN): Think of slide 6 and the numbers on slide 7. SAY (FA): به اسلاید ۶ و عددهای اسلاید ۷ فکر کنید. KEY POINT: Answer on the next slide. EXAMPLE: — PITFALL: — ASK: Who picked D? What did lab 05 show? TIME: 45
Answer: C

Only store→load: the store buffer delays the store

A full barrier (mfence or a locked instruction) drains the store buffer before the next load.

linux/arch/x86/include/asm/barrier.h · __smp_mb() · L53 · v6.18.63

SAY (EN): x86 keeps store order and load order; the only visible reordering is a store followed by a load from a different address. The kernel's smp_mb() on x86 is lock addl $0 on the stack. SAY (FA): x86 ترتیب storeها و ترتیب loadها را نگه می‌دارد؛ تنها جابه‌جایی دیدنی یک store و بعد loadی از آدرس دیگر است. smp_mb() کرنل روی x86 همان lock addl $0 روی stack است. KEY POINT: TSO = SC minus store→load. EXAMPLE: lab 05 solution/mp.c: message passing never fails on x86. PITFALL: Concluding relaxed code is portable because it works on x86. TIME: 60
